MultiLog — sample dataset for testing the new architecture
==========================================================

PROVENANCE — READ THIS FIRST
----------------------------
This dataset is PARTLY SYNTHETIC. It exists to exercise every code path in the
new architecture, not to represent real measurements.

  Real      : the point cloud tables and the image streams, both derived
              from data/Example/lidar_scene0.csv and its JPG frames.
              (drive_02's Height column is offset by +1.5 m so the two logs
              are visibly distinguishable.)

  SYNTHETIC : the point-cloud backdrops (*.cloud.h5) and every curve
              (*.curve.h5) were generated by a script — random points on a
              ground plane with walls, and Gaussian "targets" over a noise
              floor. They are NOT sensor output. Do not read anything into the
              detection levels, target ranges, or noise statistics.

  SYNTHETIC : drive_01.rear.mp4 is a duplicate of drive_01.mp4, present only to
              exercise the multi-image-stream path.

What it covers
--------------
Two logs sharing one case folder, associated by basename:

  drive_01   table + cloud + curve (2 plots) + 2 image streams
  drive_02   table + cloud + curve (1 plot)  + 1 image stream

This exercises: the flat basename layout, per-log sidecar resolution, log
switching, multi-stream images, config-driven 1D curve plots with per-trace
styling, and frame index derivation from Parquet.

The curve block in info.json is hand-authored (colors, dash styles, two plots
on two different x axes) to show what the config can express. The ingest
pipeline emits a plainer starter config that you then edit.

Regenerating
------------
The raw source is in ../_raw/multilog. To rebuild this dataset:

    python -m dataio.ingest ./data/_raw/multilog --out ./data/MultiLog

Note that re-running ingest overwrites info.json with the auto-generated
starter curve config, discarding the hand-authored styling above.
